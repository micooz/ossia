## 交付目标

基于 `14da38f` 完成引擎模块、macOS ARM64 原生验证和五目标构建配方。

不启动 Linux 环境。P00 的 Linux ARM64 门槛保留；本轮交付后 P02 标记为“本机实现完成、未集成，受前序门槛阻塞”，不标记已验收。不进入 P03、不接 UI、不发布、不处理用户数据。

## 工具链与模块

- 新增 `crates/ossia-engine`，加入根 workspace，依赖现有 types／score；不依赖 GUI、数据库或 Node.js 服务。
- `vendor/ENGINE.lock` 改为版本化 JSON，由 Rust 和开发脚本共同读取；按五目标记录来源、版本、归档格式、SHA-256、入口、运行依赖和构建标识。
- 官方四目标使用固定的 2.26.0 归档；Linux ARM64 固定源码、上游打包脚本、依赖来源与校验和，提供原生构建配方。未生成的包记录为未构建，不填造产物哈希。
- 开发脚本下载、校验和准备资源，生成文件完整性清单；保留目录、权限和必要时间戳，包含转换器、Python、字体和非系统运行依赖。
- Rust 接受显式工具链根目录，或从调用方提供的安装资源目录定位；不搜索系统 PATH、不依赖 cwd、不修改签名后的资源。

## 公共接口与执行行为

- 提供同步 `Engine::verify`、`convert`、`compile`，显式传入工具链、不可变输入、选项、取消上下文和产物根目录。
- 在 types 中增加导入报告、诊断、产物引用和 RenderManifest；camelCase JSON，格式分别报告结果，SVG 不因 PDF／MIDI 不支持失效。
- `.ly` 验证 UTF-8，静态检查标准库与外部依赖，动态 include 返回 unsupported-source；不因无法索引而拒绝合法源码。
- MusicXML／MIDI 用固定临时文件名转换并规范化临时路径；保留 clean／needs-confirmation／refused，确认绑定输入、引擎和损失摘要，Negative skip 始终拒绝。
- 每次调用使用独立 scratch、HOME、缓存；直接启动程序并传参。Unix 进程组、Windows Job Object 负责取消／超时后的全树回收，所有退出路径清理目录。
- SVG、PDF 分 pass 执行。优先通过引擎选项启用锚点；源码有覆盖时只修改派生副本并建立位置映射。
- MIDI 优先使用有效块，补充只针对能唯一识别的完整 score 块；无法安全处理只拒绝该格式，不修改节奏、速度或公共源码。
- 数值页码排序；缺页、无请求产物、多 book 或归属不唯一明确失败；解析 MIDI，拒绝空结果。
- 原始诊断经 P01 SourceMap 映射回快照，不确定位置留空；日志和 SVG 回链去除机器路径，标准库位置不冒充用户源码。
- 缓存键含源码、引擎、选项、格式；内容寻址文件先写、清单最后原子发布，同键加锁。重启校验文件，损坏／缺失重建，拒绝路径逸出。
