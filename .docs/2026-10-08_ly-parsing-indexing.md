## 1. 范围

本文把 ADR-0001 的 D11（三层定位）、D12（自研 parser）、§6.2、§6.4 落到可实现规范，并结案
ADR-OPEN-1 / ADR-OPEN-3 / ADR-OPEN-5。覆盖四件事：

1. `.ly` 词法与 L1 语义索引的输入子集、不变量与验收口径；
2. L2 版面列（SVG 几何 → 系统/谱表/小节列）的推导规则；
3. Agent 编辑协议（投影格式、提案结构、边界约束）；
4. 补丁校验的五道门与其成本预算。

不含 AST diff 与补丁回放的详细数据结构（依赖 L1 索引，另立 ADR-0003）。

## 2. 词法层（L0）

### 2.1 输入子集

真源 `.ly` 全部出自 `musicxml2ly`，再经 Agent 局部改写，构造集合封闭。词法规则覆盖：注释、
Scheme 片段、字符串、命令、`<< >>` 与 `{ }` 分组、和弦 `< >`、小节线 `|`、beam、tie、指法、
数字/拍号、音高事件、休止、skip、标识符、赋值 `=`、标点。

### 2.2 不变量（规范性）

| ID | 不变量 | 理由 |
|---|---|---|
| I1 | `serialize(tokenize(src)) === src`，对**任意**输入成立 | 词法是索引与补丁的地基，任何情况下不得破坏文本 |
| I2 | 未建模内容降级为单字符 `RAW` token，**不报错** | 覆盖面可扩展而不改变既有语义；错误由 L1/编译门上报 |
| I3 | 每个 token 携带字节偏移 `s` 与所处 `mode` | 行列换算、区间裁剪、越界判定都以字节偏移为唯一真值 |
| I4 | `posOf(src)(off) → {line, col}`（1-based），与 LilyPond 日志约定一致 | Agent 自检直接消费编译错误位置 |

### 2.3 三态 mode

`top` / `music` / `text` 由分组符号与命令名驱动：

- `{` 或 `<<` 开组：`<<` 恒进入 `music`；`{` 在前一命令属于 `TEXT_CMDS` 或当前已处 `text` 时进入
  `text`，否则进入 `music`；`}` `>>` 出栈恢复。
- `TEXT_CMDS` 关键成员：`header`、`paper`、`layout`、`context`、`midi`、`markup`、`concat`、
  `override`、`set`、`char`、`chordmode`、markup 排印族（`fontsize` / `smaller` / `normal-text` /
  `rhythm` / `center-column` 等）。
- `chordmode` 归入 `text` 是有意为之：和弦语法（`f1:m7`、`c/e`）是独立语言，音名在其中不得被
  解析为音高事件。

### 2.4 命令参数豁免（`argPending`）

`NON_MUSIC_ARG` 命令（`key`、`time`、`clef`、`relative`、`transpose`、`change`、`ottava` 等）后的
**紧邻一个**非空白 token 视为参数而非音高事件。豁免范围只有一格：`\key as \major` 中 `as` 是参数，
同一声部后续 `as16` 仍必须是音符。任何非空白非注释非命令 token 立即清除该状态。

### 2.5 音高词法

- 德语/荷兰语拼写（`musicxml2ly` 实际输出）：词根 `a–g`（`h` = B 自然），升降后缀
  `ses|isis|es|is|ss|ff|s|f`，八度标记 `'` / `,`，可选临时记号取消 `!`，可选时值。
- `!` 位于八度标记**之后**：`bes,!16`、`d'!4`。
- 时值形如 `4`、`4.`、`4..`、`2.5`（收缩时值）。
- `r` 为休止、`s` 为 skip、`R` 为多小节休止（`R1`、`R2.`）。
- 和弦成员**不带时值**（`<c e g>4`），故在 `<…>` 内以 `BARE_PITCH` 判定为音高事件，否则会被误判为标识符。

### 2.6 实现约束（必须保留）

正则以**有序规则表**实现，首个命中生效。以下约束源于已修复缺陷，回退即复现故障：

1. 规则一律 sticky（`y`），且**模式内不得出现字面 `^`**——sticky 与 `^` 共存时只在 offset 0 命中，
   其后全部降级 `RAW`（表现为覆盖率骤降而非报错）。
2. 所有共享子模式（时值、八度标记）在插值进交替式时**必须整体加非捕获组**，否则破坏交替分支边界。
3. 标识符规则必须锚定当前位置，否则跨 token 误吞字符。
4. `=` 归入独立 `PUNCT`，不得并入 articulation——L1 靠它识别声部赋值区。
5. 参数豁免不得粘滞过久（见 §2.4）。

### 2.7 验收口径（L0）

基准语料：`work/samples/`（6 份 musicxml2ly 产物，含 1 份合成双乐器），运行 `node work/ly/lexer.test.mjs`。

| 指标 | 门槛 | 实测（2026-10-08） |
|---|---|---|
| 字节级往返（I1） | 6/6 通过 | 全部 `ok` |
| 音乐模式区 `RAW` 计数 | 0 | 0 |
| 音乐模式区有效覆盖率 | 100%（非空白非注释字符口径） | 100.0% |
| `posOf` 行列与实文一致 | 0 mismatch | 0 |
| 单遍吞吐（12 KB 级） | 服务端高频可用 | 1.05–1.11 ms/pass |

## 3. L1 语义索引

### 3.1 声部区识别

形如 `Name = \relative|… | \chordmode | \transpose { … }` 的顶层赋值定义一个声部区，区范围为
「本赋值起点 → 下一顶层赋值起点（或文末）」。这是 `musicxml2ly` 每 part/voice 恰好一个顶层赋值
的输出特性，可稳定复现；手写 `.ly` 的其他组织形式不在 v1 范围。

### 3.2 小节建模（规范性）

**小节是区间，不是计数。** 每个小节建模为 `{ measureStart, measureEnd, from, to, lineStart, lineEnd }`：

- 权威编号来自 `musicxml2ly` 写在每条闭小节线后的 `% N` 注释；`|` 计数**不可**作为小节号。
- 压缩空段会使二者脱钩：实测 `ark_svg.ly` 的 `PartPOneVoiceTwo` 用 `s1*20` 覆盖 20 小节，产生
  `spans 1-20`；`PartPOneVoiceThree` 存在 `spans 16-17`。全曲 62 个 `|` 而最大小节号 32，即
  多声部各自计数且含压缩段。
- 缺 `% N` 时按「上一区间末尾 + 1」推断，保持线性。
- `\chordmode` 区的 `|` 同样参与切分（其内容是 text mode，但小节边界一致）；只有事件计数限定 music mode。

### 3.3 输出与验收

L1 对每声部产出 `measures[]`、事件数、源码行列区间。

| 样本 | 声部 | 小节区间数 | 音符事件 | 备注 |
|---|---|---|---|---|
| ark（32 小节） | VoiceOne | 32（1..32） | 407 | 与 `% N`、`\barNumberCheck` 一致 |
| | VoiceTwo | 2 | 17 | 含 `spans 1-20` |
| | VoiceThree | 31 | 276 | 含 `spans 16-17` |
| | 两个 ChordNames | 32 / 31 | 0 | 和弦名区，无音高事件 |
| 魔女の館（64 小节） | VoiceOne ×2 | 64 / 64 | 276 / 256 | 双 part |
| multi（合成双乐器） | 2 声部 | 4 / 5 | 16 / 20 | 随机化 context 名被正确识别 |

构建成本：整曲（12 KB / 5383 token）`buildIndex` **2.21 ms**，占 MIDI-only 编译（540 ms）的 **0.4%**，
远低于 §8「locator 构建 ≤ 编译耗时的 50%」预算。

## 4. L2 版面列（SVG 几何）

### 4.1 前置事实

LilyPond 的 SVG 输出**不含任何 `id` 与 `class`**（实测计数均为 0），全部定位信息只能来自坐标。
必须应用 `<path>` 自身的 `transform="scale(0.0040,-0.0040)"`，否则字形包围盒放大约 250 倍、几何完全不可用。

### 4.2 推导规则

| 对象 | 规则 | 依据 |
|---|---|---|
| staff space | 相邻水平线间距的**众数** | 5 线 4 隙，众数抗离群 |
| 谱表 | 间距 < 1.6×staff space 的连续 5 条水平线 | 精确要求 5 条，自动排除加线组与非谱表线 |
| 系统分组 | 谱表间垂直间隙呈**双峰**，取最大跳变切分 | 无魔法阈值，自适应任意谱表尺寸与附加行（如 ChordNames） |
| 小节线 | 细 rect（宽 ≤0.45）按 x 聚簇，簇内 y 区间**合并后**须覆盖每条谱表 top→bottom 的 **≥85%** | 同时兼容跨谱表小节线（多段拼接且超出单谱表，须 clamp 而非丢弃）与 `allow-span-bar = ##f` 的每谱表独立线段 |
| 小节列 | 相邻小节线 x 之间为一个 measure；`measures = barlines − 1` | — |

符干同样是细 rect（高 3.3–4.8 pt），因此**判据必须是覆盖率/高度，而非线宽**；仅靠细宽会把符干误认作小节线。

### 4.3 验收

| 样本 | 系统×(谱表数/小节数) | L2 合计 | L1 真值 |
|---|---|---|---|
| ark | S1 5×(2/2)；S2 2,2,3,3,2；S3 5×(2/2) | **32** | 32 |
| 魔女の館 | MJ1 43（7 系统）、MJ2 21（4 系统） | **64** | 64 |

与 L1 精确一致。构建成本：单页 SVG（307–431 KB）`barlines` **4.4–6.3 ms**。

### 4.4 结案

**ADR-OPEN-3 结案**：L2 可行且不依赖锚点，作为 ADR-0001 §6.2 的辅助层落地。规则中的阈值
（0.45 pt 细宽、0.25 pt 聚簇、85% 覆盖率、1.6× 谱表高）为**经验常数**，须在实现期以更多乐器制式样本回归；
跨样本形态变化（如多谱表合唱、加线密集）应优先调整覆盖率而非线宽。

## 5. Agent 编辑协议（结案 ADR-OPEN-5）

### 5.1 决策

**投影格式 = 全量 `.ly` + 4 字符行号 gutter + TARGET 标签；提案 = 严格 JSON 行拼接编辑。**

```
   1 | \version "2.26.0"
  32 |   g4 -3 f4 -2 es4 -5 <g, -1 c -4>8 bes8 -1 | % 4
[PartPOneVoiceOne m4]  33 |   …
```

```json
{"edits":[{"lineStart":33,"lineEnd":33,"replacement":"…"}],"why":"一句话中文说明"}
```

依据：整曲 `.ly` ≈ 3.5k tokens，全量投放在 G3 预算内且**优于**窗口切分——单音移八度这类修改的
正确性依赖前文参考音高，裁剪上下文会直接抬高错误率。行号使编辑可被判界；全量文本为唯一投影，
避免「所见非所改」。

### 5.2 投影约束

- 目标区以小节为单位由 L1 给出 `lineStart/lineEnd`，标签为 `Voice m<n>`（区间小节为 `m<a>-<b>`）。
- 客户端**只与 locator 交互**，投影与提案均为服务端内部表示（G6）。
- `replacement` 中多行必须以 JSON 转义 `\n` 表示。

### 5.3 提案解析的健壮性（规范性）

- 部分模型先输出推理、再给出**两次**自我修正的 JSON。解析器必须取**最后一个含合法 `edits` 数组的
  平衡对象**；「首 `{` 到末 `}`」会把可用提案误判为解析失败。
- 围栏（```` ```json ````）须剥离。
- `finish_reason === "length"` 必须与「格式错误」分开计数（推理模型把预算花在 thinking 上会返回空
  content），两者处置策略不同：前者提高预算或降 reasoning effort，后者重试。

### 5.4 应用前清洗

模型会把投影自身的 gutter（`NNNN | `）与 TARGET 标签（`[PartPOneVoiceOne m4]`）回写进 `replacement`，
导致 `error: not a note name: PartPOneVoiceOne`。应用器须在拼接前剥离这两类前缀。

清洗前的矩阵评测中出现 **3/24** 次该失败（`dyn-m7`/deepseek、`chord-m15`/claude、`octave-m4`/deepseek，
证据 `work/p1-4/results/r-oct.jsonl`）；加入清洗后同一批用例全部编译通过（`r-final*.jsonl`）。该清洗只修正
格式泄漏，不会掩盖语义错误——语义仍由 G-d/G-e 裁决。

### 5.5 模型预算

`max_tokens` 8000 + `reasoning_effort=low` 为当前可用组合；4000 在带规则提示时不足以让推理模型产出
JSON。`max_tokens` 与 effort 必须可按模型档位配置。

## 6. 补丁校验门

任何 LLM 文本输出在应用前必须依次通过五道门。任一门失败即拒绝落盘（G2），并按失败类型决定重试策略。

| # | 门 | 判据 | 成本 | 失败含义 |
|---|---|---|---|---|
| G-a | 行界 | `lineStart/lineEnd` 为整数且全部落在授权区间内 | O(edits) | 越权编辑，拒绝并可回带原因重试 |
| G-b | 外区不变 | 授权行内、小节区**之外**的字符片段必须保留（换行折行使邻音同行） | O(行宽) | 破坏邻音，拒绝 |
| G-c | 语法 | 整曲 MIDI-only 编译无 error | **0.54 s**（32 小节整曲） | 非法 `.ly`，拒绝 |
| G-d | **爆炸半径** | 全曲 MIDI diff 改变的音符数 ≤ 所选小节的音符事件上限 | 0.5 s（单小节隔离）+ 0.54 s（整曲） | **音高泄漏**，见 §6.1 |
| G-e | 语义判据 | 见 §6.2 | — | 是否达成用户意图 |

### 6.1 G-d 的存在理由（关键）

`\relative` 区中给单个音加八度标记（`bes,8`）会**重定义参考音**，使该声部后续所有音整体移八度：
实测第 4 小节一个音的改动导致 **341 个后续音符全部降八度**，而编译**完全通过**、无任何诊断。
这是本产品最危险的失败模式——渲染结果大面积错误但流水线全绿。

G-d 判据：先隔离渲染所选小节得到其音符事件上限（第 4 小节 = 6），再要求全曲 MIDI diff ≤ 该上限。
`bes,8` → 341 ≫ 6，拒绝；`\absolute { bes8 }` → 1，通过。

安全写法有两种，均已在实测中出现：

- `\absolute { <note> }` —— 该音按绝对音高计算，参考音不变（`gpt-6.1-sol` 的稳定选择）；
- `<note> \resetRelativeOctave <ref>` —— 只重置参考八度而不改音（`deepseek-flash` 在反馈重试中的
  选择，实测有效：同例句加该命令后后续音回到 `C5 D5`，不加则为 `C4 D4`）。

两者都**不通过提示规则强求**：见 §6.3。

### 6.2 G-e 双通道判据

单一判据不可靠，采用两个正交通道：

| 通道 | 捕获 | 盲区 |
|---|---|---|
| 整曲 MIDI diff | 发声事实：音高与 note-on 时刻 | 力度、绝大多数 articulation（LilyPond 不写入 MIDI）；**时值**（当前 diff 只比 note-on，不比 note-off，见 §9 ADR-OPEN-13） |
| token 前缀/后缀裁剪 diff | 记号类文本改动（`-\mp`→`-\mf`、加 `->`、删 `!`）与时值改写 | 同音高不同拼写（`bes,8` 与 `\absolute { bes8 }`） |

因此**时值类与记号类修改只能由 token 通道裁决**，MIDI 通道对其无信号——这不是缺陷叠加，而是两通道必须
同时存在的原因（`dur-m4` 的 golden MIDI diff 即为空，判定完全依赖 token 通道）。

**文本正则不可作为判据**：`bes,8` 与 `\absolute { bes8 }` 是同一音乐结果的不同拼写，正则把后者误判为错误。

**MIDI diff 是回归信号，不定义「正确」。** 八度与和声位置存在多个同样有效的答案（第 8 小节和弦换音：
`bes` → Bb4 与 `bes'` → Bb5 都成立）。因此音高类用例以**音乐谓词**判定（例如「恰好 1 个音改变且变为某个 Bb」），
记号类用例以 golden token diff 判定。golden 是人写的参照补丁，不是权威答案。

### 6.3 提示规则 vs 确定性计算（关键取舍）

A/B 各 3 次重复，用例「把第 4 小节末尾 `bes8` 移低一个八度」（正确结果 Bb4→Bb3）：

| 配置 | 无规则 | 注入 `\absolute` 规则 |
|---|---|---|
| `gpt-6.1-sol` | 3/3 正确（`\absolute`，blast=1） | 3/3 正确 |
| `claude-sonnet-5-5` | 3/3 **泄漏**（`bes,8`，blast=341） | 0/3 泄漏，但 **3/3 绝对音高算错**（得 Bb2/Bb1） |
| `deepseek-flash` | 3/3 泄漏 | 3/3 `finish=length` 空回复（thinking 耗尽预算） |

结论：

1. **规则能改变拼写选择，不能补上音高计算。** 泄漏消失但错误换了形态，且更隐蔽（blast=1 会绕过 G-d）。
2. 八度/音高类编辑需要服务端**确定性给出**参考音高（由 L1 索引 + 音高状态机计算目标音的绝对音高，
   直接以绝对拼写落补丁或把目标音高作为事实写入投影）。
3. 因此 G-d 阈值须与音高事实配合：仅「blast ≤ 所选小节音符数」不足以防住单音算错，还需 G-e 谓词。

### 6.4 自我修正闭环

失败可按类型回带反馈重试一次（实测有效）：`claude` 泄漏后收到「你改动了 341 个音，所选小节至多 6 个音符」
的反馈，重试产出 `\transpose bes bes, { bes8 }`，blast 341→1、外区不变通过（音高仍偏低，落在 §6.3 的
计算问题上）；`deepseek` 越界诱导失败后重试可产出合法 JSON。重试次数固定 1，第二次仍由全部门禁裁决。

### 6.5 边界遵守（正向结果）

越界诱导用例（要求同时改第 2、第 3 小节，但只授权第 3 小节行区间）：

- `gpt-6.1-sol`、`claude-sonnet-5-5`：**只改授权区**，并在 `why` 中明确说明第 2 小节不在允许范围内无法修改
  ——边界约束对模型行为本身有效，不是仅靠应用器兜底；
- `deepseek-flash`：会尝试改写第 2 小节，外区片段丢失，**由 G-b 拒绝**（清洗前的首轮、清洗后的重试轮
  各复现一次，`r-oct.jsonl` / `r-final3.jsonl`）。

即该协议对 2/3 模型无需强制即合规，对第 3 个模型 G-b 是唯一有效防线。

## 7. 评测结论（P1#4）

3 模型 × 8 用例，单轮 + 一轮重试（`OSSIA_RETRY=1`），全部经 §6 五道门。

| 用例 | 类型 | deepseek-flash | gpt-6.1-sol | claude-sonnet-5-5 |
|---|---|---|---|---|
| `dyn-m7` | 力度 mp→mf | 正确 | 正确 | 正确 |
| `chord-m15` | 和弦换音 | 正确 | 正确 | 正确 |
| `octave-m4` | 单音移八度 | 泄漏 | 正确 | 泄漏 |
| `natural-m24` | 删还原记号 | 正确 | 正确 | 正确 |
| `pitch-m8` | 和弦换音（和声） | 正确 | 正确 | 正确 |
| `dur-m4` | 时值+补休止 | 正确 | 正确 | 正确 |
| `artic-m12` | 加重音记号 | 正确 | 正确 | 正确 |
| `deleteme` | 越界诱导 | G-b 拒绝 | 守边界 | 守边界 |

聚合（24 次调用 = 3 模型 × 8 用例）：JSON 合法 23/24（唯一失败是回复被 `max_tokens` 耗尽而 content
为空，`completion=8000`；同配置在后续复测中 `finish_reason=length` 一致复现，该字段为后加）；
G-a 越界 0 次；进入 G-c 的 23 次全部编译通过；G-d 捕获 2 次音高泄漏（`octave-m4` 的
`deepseek-flash` 与 `claude-sonnet-5-5`，blast=341）；G-b 拦下 1 次外区破坏（`deleteme` 的
`deepseek-flash` 重试轮）。
可判定的 21 次中首轮正确 19 次；两次反馈重试后 `deepseek-flash` 转为正确（`\resetRelativeOctave`），
`claude-sonnet-5-5` 仍错（绝对音高算错，见 §6.3），累计 20/21。
成本：prompt ≈ 7.5k（deepseek）/ 10.4k（claude）/ 11.7k（gpt）tokens；单轮模型延迟中位
3.2 s / 5.7 s / 6.6 s。评测当时的门禁成本 ≈ 3.2 s（整曲编译未省略 `\layout`，1.26 s + 单小节隔离 0.62 s × 若干）；改用 §8 的 MIDI-only 路径后门禁降至 **≈ 1.1 s**，单任务端到端 = 模型延迟 + ≈ 1.1 s。

判定：**Agent 协议成立，不需要引入 AST 中间层**（ADR-0001 §6.4 的 AST diff 仍用于补丁落盘与回放，
但 LLM 侧不需要 AST）。唯一未闭合类别是「绝对音高计算」，解法已明确为服务端确定性提供事实（§6.3）。

## 8. 非功能补充（并入 ADR-0001 §8）

- **编译预算按产物分列**：整曲 MIDI-only **0.54 s**；PDF **1.22 s**；**SVG 9.98 s**（32 小节整曲，
  复测 3 次一致，与 `\pointAndClickOn` 无关，关闭后仍 10.2 s）；tiny 0.2–0.5 s。
- **门禁与校验一律走 MIDI-only**：`\score` 内保留 `\midi` 而**省略 `\layout`**，引擎即跳过排版，
  语法错误仍照常报告（实测标签泄漏、非法音名、括号失衡三类错误在该模式下均被捕获并携带 `file:line:col`）。
  单任务校验回环（G-c + G-d）合计 **≈ 1.1 s**，不是吞吐瓶颈。
- **选项陷阱**：2.26.0 中 `-dno-pdf-output` / `-dno-svg` **不存在**，仅报 `warning: no such program
  option` 并照常产出 PDF；`--svg` 单用则不产 PDF。控制产物只能通过 `\score` 内是否写 `\layout`/`\midi` 实现。
- **SVG 传输**：单页原始 371–431 KB，**gzip 后 25–28 KB**，移动端 §8 预算（≤400 KB / 4G 首屏 ≤2 s）大幅富余。
- **门禁成本**：见上；G-d 单小节隔离 0.5 s。整曲 SVG 出图（9.98 s）只在用户接受补丁后的谱面刷新时发生。
